# Intake contract

## Minimum viable input

Proceed when the following can be determined from files or the request:

- Product or feature name
- Target user or audience
- Primary task or decision
- Current artifact: screenshot, HTML, source, prototype, or written flow
- Desired outcome
- Target device or viewport

Label anything else as unknown rather than inventing it.

## Preferred input

- User research or support evidence
- Analytics definitions and observed values
- Current user flow
- Business goal and guardrail metrics
- Design tokens and component usage rules
- Content rules and terminology
- Accessibility target
- Technical and policy constraints
- Known non-goals

## Evidence labels

Use these labels in audits and rationale:

- `OBSERVED`: directly visible or mechanically inspected
- `REPORTED`: supplied by a stakeholder or research artifact
- `INFERRED`: professional judgment that still needs verification
- `UNKNOWN`: needed but unavailable

## Decision gates

Request a human choice before proceeding when alternatives would change:

- The primary target user
- The core product promise
- The success metric
- Data collection or privacy behavior
- Irreversible navigation or information architecture

Proceed with a documented recommendation for reversible layout, wording, hierarchy, and component choices.
