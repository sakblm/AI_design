# Product design review framework

Review in this order.

## 1. Outcome and task fit

- Is the intended outcome clear?
- Does the flow help the user make the required decision?
- Are success and exit states explicit?

## 2. Information and uncertainty

- Are inputs, constraints, sources, and uncertainty visible?
- Can the user understand why a recommendation or result appeared?
- Can the user revise an incorrect assumption?

## 3. Flow and state

- Are prerequisites requested at the right time?
- Is progress preserved?
- Are empty, loading, error, partial, and recovery states designed?
- Does the user know what happens next?

## 4. Choice and comparison

- Are options comparable on decision-relevant attributes?
- Is the number of choices manageable?
- Are defaults and recommendations explainable?

## 5. Trust and control

- Can the user verify important claims?
- Are destructive, paid, external, or irreversible actions clear?
- Can the user undo, go back, or edit?

## 6. Accessibility and content

- Is structure semantic and keyboard navigable?
- Is visible focus preserved?
- Are labels meaningful without positional context?
- Does the layout survive realistic Japanese text length?

## 7. Visual system

- Are tokens and components used consistently?
- Does hierarchy reflect task importance?
- Are spacing and density intentional?

## Finding format
